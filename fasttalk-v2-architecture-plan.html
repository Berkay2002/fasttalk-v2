The decision

Desktop shell

Tauri 2, not a browser-only app

React renders the UI. Rust owns audio, state, resource admission, and native worker supervision. The WebView never becomes the inference runtime.

Inference

Native Windows CUDA sidecars

NeMo-Speech.cpp serves streaming speech. llama.cpp serves Qwen. Native workers give direct CUDA access and normal Windows lifecycle control.

Deployment

No Docker at runtime

Docker and WSL2 remain optional development tools. Users need a compatible NVIDIA driver, not Docker Desktop, CUDA Toolkit, Python, Node, or Rust.

Profile-driven VRAM policy

Qwen3.5 + ASR measured worker delta7.90 GB
Magpie measured incremental delta0.93 GB
Observed desktop baseline3.14 GB
Required reserve≥1.5 GB
Admission order
  1. Select a named runtime profile compatible with the detected GPU.
  2. Compute the admission ceiling from detected total VRAM minus the profile reserve.
  3. Load the profile's LLM and ASR, then compare actual usage with its measured worker deltas.
  4. Load GPU TTS only when it fits; otherwise use the profile's CPU fallback.
Artifact size is not peak VRAM. The decision is made from a combined warmed benchmark while normal desktop applications are open. The current RTX 3090 profile selects Qwen3.5 9B Q5_K_M because Qwen3.6 27B missed the 20 token/s gate. Other hardware is described by another profile rather than a hardcoded 24 GB assumption.

Why Docker is not shipped

Docker Desktop GPU support crosses Windows, WSL2, a Linux VM, container networking, and bind-mounted model files. It adds daemon startup and failure states while the microphone and speakers remain native Windows resources. Riva NIM additionally requires NVIDIA AI Enterprise. Native NeMo-Speech.cpp and llama.cpp avoid those constraints.

Implementation sequence

Hardware feasibility spike

Build pinned native runtimes, run Qwen3.6 + Nemotron + both TTS options, capture TTFT, throughput, first audio, RTF, VRAM, and cancellation. Apply the fixed gates before building the UI around assumptions.

Core conversation engine

Implement the typed provider interfaces, explicit state machine, endpoint policy, prompt/session manager, clause chunker, interruption semantics, and deterministic cancellation.

Native audio and supervision

Add WASAPI capture/playback, playback-reference AEC, resampling, binary audio transport, Windows Job Objects, health checks, crash recovery, and bounded diagnostics.

Polished desktop experience

Build a restrained conversation UI with setup progress, device selection, live transcript, readiness, clear listening/thinking/speaking states, mute, stop, and manual interrupt.

Model manager and offline setup

Use pinned Hugging Face revisions, signed manifests, resumable downloads, SHA-256 verification, atomic activation, license notices, and air-gapped model packs.

Installer and release gate

Package a current-user NSIS installer, private CUDA runtime dependencies, VC++ prerequisite, signatures, clean-machine verification, offline tests, and uninstall coverage.

Cross-profile benchmark matrix

After the baseline release is verified, discover similarly rated local LLM, STT, and TTS candidates on Hugging Face, express compatible combinations as runtime profiles, and run the existing isolated, integrated, acoustic, fault, and soak harnesses against them. Preserve passing and failing results as versioned empirical evidence.

Final cross-profile benchmark matrix

Candidate admission

  1. Use authenticated Hugging Face discovery to find similarly rated, actively maintained candidates in each component class.
  2. Record exact repository revision, artifact hash, quantization, license, language coverage, runtime support, and Windows CUDA or CPU compatibility.
  3. Reject candidates that need an unrelated serving stack, cannot stream, do not fit the detected hardware with reserve, or cannot be redistributed under the product's packaging model.
  4. Add admitted candidates as named entries in runtime-profiles.json; do not branch product code per model.

Staged matrix, not a blind Cartesian product

  1. Benchmark each LLM, STT, and TTS candidate in isolation with fixed inputs and warmup.
  2. Run pairwise memory and cancellation checks for candidates that pass their component gates.
  3. Run full end-to-end turns only for combinations that fit the profile reserve.
  4. Run acoustic scenarios, fault injection, and the 30-minute soak for finalists.

Release scenarios

  • Quiet speech, hesitation, short acknowledgements, long questions, background noise, and speaker playback.
  • Rapid interruption during LLM generation, TTS synthesis, and active playback.
  • Worker crash, corrupt model, partial download, port conflict, unavailable microphone, and insufficient free VRAM.
  • Clean Windows installation with an NVIDIA driver but no CUDA Toolkit, Docker, WSL, Python, Node, Rust, or Visual Studio.
  • Complete voice turn, restart recovery, and normal operation with networking disabled.
